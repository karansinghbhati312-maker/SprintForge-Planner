Build a complete full-stack MVP called “SprintForge” for this assignment:

Product: PRD → Sprint Planner

Purpose: A product manager enters a feature idea. The system converts it into a structured PRD, user stories, engineering tasks, priorities, effort estimates, dependencies, and sprint allocations.

Use the simplest reliable Replit-compatible stack:

- React + TypeScript frontend
- Express + TypeScript backend
- SQLite database
- Clean responsive CSS or Tailwind if already configured
- Rule-based generation by default so the app works without an API key
- Optional OpenAI integration only when OPENAI_API_KEY exists
- One Replit run command that starts the complete application

Do not add authentication, payments, teams, email, or unnecessary features.

USER WORKFLOW

Create a “New Plan” page with a structured form containing:

- Feature title
- Feature description
- Target users
- Business goal
- Main problem
- Must-have requirements
- Nice-to-have requirements
- Constraints
- Desired sprint length: 1–4 weeks
- Team capacity in story points
- Number of available sprints

After submission, send the data to the backend and generate:

1. PRD
   - Executive summary
   - Problem statement
   - Target users
   - Goals
   - Non-goals
   - Functional requirements
   - Non-functional requirements
   - Assumptions
   - Risks
   - Success metrics
   - Acceptance criteria

2. User stories
   - Title
   - “As a / I want / So that” statement
   - Acceptance criteria
   - Priority
   - Effort points

3. Engineering tasks
   - Task title
   - Description
   - Category: frontend, backend, database, testing, or deployment
   - Priority
   - Effort points
   - Dependencies
   - Assigned sprint

SMART RULE-BASED LOGIC

Implement transparent deterministic logic:

Priority score from 0–100:

- Business value: 35%
- User impact: 30%
- Urgency: 20%
- Risk reduction: 15%

Convert score into:

- 80–100: Critical
- 60–79: High
- 40–59: Medium
- 0–39: Low

Effort must use Fibonacci values: 1, 2, 3, 5, 8, or 13.

Use keywords and requirement complexity to estimate effort. Display the reason for each estimate.

Detect basic dependencies using task categories and keywords. Apply these rules:

- Database/schema work precedes backend API work
- Backend API work precedes connected frontend work
- Implementation precedes testing
- Testing precedes deployment
- A task cannot be assigned before its dependencies

Allocate tasks into sprints by:

- Priority first
- Dependencies second
- Available capacity third
- Never exceeding the configured sprint capacity
- Clearly marking unallocated tasks when capacity is insufficient
